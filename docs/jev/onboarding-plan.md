# Onboarding installer plan (T-51060f4d)

Author: jev-architect (persisted by the orchestrator). Repo root: E:/Development/jev-orchestrator (all paths below are relative to it). Host facts and support labels come only from docs/jev/host-research.md.

## objective
Ship one cross-platform onboarding installer, `scripts/onboard.py` (Python 3.9+, standard library only), with thin `install.sh` / `install.ps1` / `uninstall.sh` wrappers. It provides an environment and host check (`--check`), model presets with per-role overrides and guardrails, safe and bypass modes with a gate self-test, an install and uninstall made reversible by a manifest and backups, checks after installing, offline tests that run against a temporary home, and a rewritten README. Claude Code gets the full harness. Other hosts are detected and reported with a support level, and nothing is installed for them.

## assumptions
- Claude Code loads hooks and agents at session start, so a restart is needed. If a hook command cannot open its script, Python exits 2 and every matched tool call is blocked (this locked a session on 2026-09-30).
- Code reading the routing config: `jev.py` config_path()/load_config() (also used by hooks/dispatch_router.py), `scripts/sync_agents.py` (own path), `jevctx.py` (reads only context_policy; presets never change it).
- `jev.py check_dispatch` (around lines 1298-1303) denies any role whose model key is not "opus" when its resolved ID equals models.opus or contains "opus". Under Z.ai both remaps are glm-5.3, so presets must not use opus/sonnet keys for GLM IDs.
- `jev.py` computes `_CFG` at import (line ~111) but `jev_home()` is defined at line ~914.
- Existing tests assert the balanced preset's IDs from whatever config is live (test_vnext.py, test_dispatch_router.py): they must pin the shipped config.
- `jevlib.LOG_DIR` and KEY_FILES use expanduser at import; on Windows Python reads USERPROFILE, not HOME. `dispatch_router.py` logs to the real ~/.claude/jev even when JEV_HOME is set.
- Owner machine: Windows 11; python is C:/Python314/python.exe; python3 is the Microsoft Store stub; the py launcher and Git Bash exist; zsh does not. Owner settings.json remaps opus/sonnet to glm-5.3 via ANTHROPIC_BASE_URL=https://api.z.ai/api/anthropic.
- install.ps1 deduplicates hooks by exact command string, so on the owner machine it would add duplicates: deduplication must match the script name.
- permission_gate.py inspects only Bash and file-edit tools (it skips PowerShell). Under permission_mode bypassPermissions every "ask" becomes a silent pass.
- The checkout uses CRLF: write generated files with LF and compare after normalising newlines.

## constraints
- Python 3.9+ stdlib only: no new dependencies, no TOML parsing, no match statements, no runtime `X | Y` types, timezone-aware datetimes only.
- Builders never run an install or uninstall against the real home. Against the real home only `--check`, `--dry-run`, `--list-presets`, `--show-routing` may run. Every test uses a temporary home plus a copy of the repo.
- No behaviour change to permission_gate.py, dispatch_router.py, prompt_router.py, jevlib.py, jevctx.py. Do not touch docs/REPORT.md.
- ASCII-only output. Never print secrets (settings env values other than the allowed model/base-URL keys, ANTHROPIC_AUTH_TOKEN, the TypeSafe key).
- Each step owns its files; parallel steps never share a file.

## owner decisions taken (defaults)
D1 routing stored in ~/.claude/jev/agents.json with rendered agent copies (not config/agents.json). D2 default components = gate + dispatch guard; prompt router and the CLAUDE.md required-stack block are opt-in. D3 v1: non-Claude hosts detected and reported only. D4 v1: bypass gaps disclosed only. D5 live e2e check offered by default in interactive bypass, otherwise opt-in with --e2e. D6 preset contents as below, no Haiku lane. D7 no strict mode in v1. D8 conditions.json seeded as [] when the router is chosen; the sample route makes one Jev call only when a key exists (--offline skips).

## risks and mitigations
- settings.json clobbered or corrupted: parse-or-abort, sha re-check before the atomic write, a backup on every run, only our keys touched, byte-exact restore when untouched.
- Secret leak: only allow-listed settings values are read, the key is entered with getpass and never on the command line, backups keep original permissions, tests grep for a planted fake secret.
- Session lock-out (a missing hook script exits 2): script-exists check and command self-test before registering, uninstall order, link kept while Claude runs, --check reports CRITICAL, README recovery steps.
- Bypass with no protection: the gate is required, a deny self-test runs in bypassPermissions, settings restore automatically when it fails, an e2e FAIL reverts to safe, --check flags unprotected-bypass. Remaining gaps disclosed, not fixed: asks pass silently; PowerShell, MCP and web tools are not inspected; an agent can edit settings.json to drop the gate for later sessions.
- Data loss through junctions: links are never rmtree'd, only verified links are removed, real dirs go to backups, tests use a repo copy and unlink first.
- Hidden or misrouted agents: rendering through sync_agents, ID and alias validation, the collision check, preflight plus check_dispatch on every preset.
- Personal GLM IDs leaking into the public repo: routing lives in ~/.claude/jev; a git status check guards it.
- Overclaiming host support: labels copied verbatim, nothing installed for other hosts, wording "registered, active after restart".
